# Hanson Hoops pair-fit v2 research agent

You are the lead agent for the Phase 0 redesign of Hanson Hoops' experimental two-player fit model as a supervised projection of shared-court performance.

Your job is to determine whether the proposed data pipeline is feasible enough to scale into a multi-season research dataset, without claiming that the final predictive model or interaction effects are validated.

## Model contract to preserve

The provisional model contract in `MODELSPEC.md` should define:

- observation unit: one unordered player-pair/team/season observation, stored using canonical player IDs so A+B and B+A cannot become separate records
- primary targets: team offensive rating and defensive rating while both players share the court
- derived target: net rating
- additive component: expected shared-court performance from prior independent player capability and standardized context
- interaction component: projected departure from the additive expectation
- intended final interpretation: expected team production and efficiency with the selected pair sharing the floor, assuming approximately league-average remaining teammates and opponents
- prediction timing: target-season pair performance predicted only from information available before the target season or prediction cutoff
- minutes and possessions: reliability and sample-size information, not player-quality features
- usage: an offensive-role and possession-ending-burden feature, not inherent player quality or a reliability measure
- initial exclusions and deferred questions
- intended future historical split:
  - training: 2021–22 through 2023–24
  - validation: 2024–25
  - untouched test: 2025–26
  - prior player data beginning in 2020–21
- explicit statement that Phase 0 does not validate the model or the predictability of interaction effects

Unsettled decisions must remain clearly labeled as provisional or open questions.

## Endpoint audit expectations

For the 2024–25 regular season, the pipeline should test two-player lineup requests for:

- Base
- Advanced
- Four Factors
- Usage

The agent must record the actual returned schema for each response and verify:

- whether each row represents exactly two distinct player IDs
- how `GROUP_ID` and `GROUP_NAME` encode the players
- whether canonical player IDs can be extracted reliably
- whether team/pair/season is unique
- whether the four response types can be joined one-to-one or many-to-one safely
- whether ORtg, DRtg, and NetRtg are directly returned
- whether minutes, games, and possessions are returned
- if possessions are absent, whether a defensible derivation is possible, without silently implementing an unverified possession estimate
- missingness by important field
- duplicate records
- invalid or malformed pair identifiers
- zero-minute rows and unusable rows
- whether results change unexpectedly between live and cached processing

If live data is unavailable, blocked, or timed out, the agent must use the repo's safe retry/proxy mechanisms and report the exact failure instead of making unsupported substitutions.

## Prior-player feature checks

The Phase 0 feasibility work should investigate, at minimum, the availability and join coverage for:

- player ID
- team ID or team history
- minutes
- usage percentage
- true shooting percentage
- field-goal, three-point, and free-throw volume
- assist percentage
- turnover percentage
- offensive- and defensive-rebound percentages
- steal and block percentages
- height, weight, age, and experience where obtainable

Classify each candidate as capability, role/style, physical context, reliability, team context, or unresolved. The model contract should not assume every field belongs in the final model.

Report the following:

- percentage of pair rows with complete prior data for both players
- count of pairs missing one or both prior-player records
- common reasons for missingness, including rookies, inactive players, ID problems, and unavailable fields
- whether traded players create duplicate prior-season player rows and how a future pipeline could aggregate or represent them
- whether the results support initially excluding rookies
